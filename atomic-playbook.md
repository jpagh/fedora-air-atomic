# atomic-playbook.md — Fedora Atomic on a MacBookAir7,2

A standalone guide to running Fedora **Atomic** (rpm-ostree) on a 2015 13" MacBook Air
(`MacBookAir7,2`): what each workaround is, why it exists, how it works, and how to undo it.

This is the Atomic counterpart to the runbook in
**[brianjcohen/fedora-air](https://github.com/brianjcohen/fedora-air)**, which covers the same
machine on Fedora **Workstation**. That runbook is where the hardware research comes from; read
it for the deeper background on the wifi card, the camera, and the suspend quirks. This document
covers only the Atomic port — and every time the two differ, the Atomic behaviour is what is
described here.

Everything below is also automated: run **`./atomic-setup.sh`** and it does the whole thing,
asking before it changes any personal preference. The sections here explain what it is doing.

## 1. Fedora Atomic, and how it differs from the original runbook

The original runbook targets Fedora Workstation with KDE Plasma. Atomic is a different animal in
ways that break most of its instructions:

| Workstation (original) | Atomic (this repo) |
|---|---|
| `dnf install` | `rpm-ostree install` — packages are **layered** into a new deployment, applied at reboot, and roll back cleanly |
| `/usr` is writable | `/usr` is **read-only** (part of the image). Writable, persistent state lives in `/etc` and `/var` |
| DKMS builds kernel modules into `/usr/lib/modules` | DKMS cannot write there. We layer **akmods**, which `akmods-ostree-post` builds for each kernel — the same mechanism RPMFusion uses for `akmod-nvidia` on Silverblue |
| Kernel modules load from the real root | The initramfs is generated by rpm-ostree; modules such as `hid_apple` and `applespi` load from it **before** the real `/etc` exists |
| KDE / PowerDevil / SDDM | Sway / swayidle / SDDM; the lock screen is a Wayland client, and there is no PowerDevil |
| `grubby` edits the kernel cmdline | `rpm-ostree kargs` |

Two consequences worth internalising:

- **`/etc` is merged into each new deployment at shutdown**, and on conflict *the local
  version wins*. So hand-edited files under `/etc` (the wifi workarounds, the sleep hooks, the
  PAM tweak) survive upgrades without extra work.
- **Some modules load too early for `/etc` to matter.** `blacklist` in `/etc/modprobe.d` cannot
  stop a module that is baked into the initramfs. This bites the `hid_apple` Fn/Ctrl swap (§7)
  and made the original runbook's `applespi` blacklist a no-op here (see the note in §8).

## 2. Using this repository

**Guided:** `./atomic-setup.sh` (run as your normal user, not with sudo). It:

1. checks the machine and that the scripts are present;
2. asks the optional questions once and saves them to `~/.config/atomic-setup/choices`
   (`--reset` forgets them);
3. layers wifi + camera (and `gtklock` if you asked for it), then tells you to **reboot**;
4. on the next run, verifies them and applies the preferences you chose;
5. prints a health check.

It is idempotent and resumable: re-run it any time and it does whatever is still missing. It
also infers "yes" for anything already present, so re-running on a configured machine asks
nothing.

**Individually:** every feature is its own script (see the README layout). They are the source
of truth; `atomic-setup.sh` just runs them in order.

**The one reboot.** Wifi and camera are layered packages, so they need a reboot to take effect.
The setup script stages both in a single transaction so you only reboot once.

## 3. Wifi — required

**Hardware:** Broadcom BCM4360, PCI ID `14e4:43a0`.

**Why the proprietary driver.** Nothing in-tree drives this card well, so it needs Broadcom's
proprietary `wl` module. That driver is unmaintained and has three defects that all need
workarounds:

1. **It does not survive S3 suspend** — after resume it associates but authentication times out.
2. **It cannot do WPA3/SAE or PMF (802.11w)** at all.
3. **It weakens kernel security mitigations** — it is not built with return thunks, so the
   kernel prints `Unpatched return thunk in use. This should not happen!` and is permanently
   tainted `P`/`O`/`E`. This is expected and documented; see §11.

**How `atomic-wifi.sh` does it.**

- Enables RPMFusion (free + nonfree) by extracting the release RPMs into `/etc/yum.repos.d`.
- Layers `akmod-wl` + `broadcom-wl` with `rpm-ostree install`. `akmod-wl` builds `wl` inside the
  new deployment via `akmods-ostree-post`; `broadcom-wl` provides the blacklist that keeps the
  in-tree drivers (`b43`, `bcma`, `ssb`, `brcmsmac`, `brcmfmac`) from claiming the card first.
- Installs three local workarounds (the files under `etc/` and `usr/` in this repo):

| File | Purpose |
|---|---|
| `/etc/systemd/system-sleep/wl-reload` | unload `wl` before suspend, reload after, and **restart `wpa_supplicant`** — without the restart the supplicant stays bound to the vanished interface and every scan fails |
| `/usr/local/sbin/wl-fix-wifi-profiles` + a `.path`/`.service` pair | rewrite WPA3/SAE profiles to WPA2-PSK, because NetworkManager saves SAE profiles that `wl` can never connect |
| `/etc/NetworkManager/conf.d/91-wl-no-pmf.conf` | default PMF off for `driver:wl`, so new profiles are not created broken |

- The sleep hook goes in **`/etc/systemd/system-sleep/`** (systemd reads hooks from there too),
  because `/usr` is read-only. SELinux labels that directory `etc_t`, which `systemd_sleep_t`
  cannot execute, so the script adds an fcontext for `bin_t` and runs `restorecon`.

**Verify:**

```sh
modinfo wl | grep filename     # .../extra/wl/wl.ko.xz
lsmod | grep '^wl'
nmcli device                   # wlp3s0, connected
```

**Known limit:** a WPA3-**only** network cannot work on this card. No workaround exists.

**Undo:** see §12.

## 4. Camera — required

**Hardware:** Broadcom 1570 FaceTime HD, PCI ID `14e4:1570`.

**Why it is awkward.** No distribution ships a driver. It needs the out-of-tree
[patjak/facetimehd](https://github.com/patjak/facetimehd) module *plus* a firmware blob
extracted from Apple's own macOS driver, which cannot be redistributed. On Workstation that is a
DKMS build and a firmware-extraction step; neither works on Atomic.

**How `atomic-camera.sh` does it.** It layers three locally-built RPMs from `atomic-camera/`:

| Package | What |
|---|---|
| `akmod-facetimehd` | the driver as an **akmod**, so `akmods-ostree-post` rebuilds it for every new kernel |
| `facetimehd-firmware` | `/usr/lib/firmware/facetimehd/firmware.bin` |
| `facetimehd` | the meta package, which also installs `/etc/modules-load.d/facetimehd.conf` |

and installs `/etc/systemd/system-sleep/facetimehd-reload` (labelled `bin_t` like the wifi one).

**The build fix you should know about.** The upstream packaging
([mulderje/facetimehd-kmod](https://copr.fedorainfracloud.org/coprs/mulderje/facetimehd-kmod/))
ships tag `0.7.0.1`, which **does not compile on kernel ≥ 7.2**: `fthd_v4l2.c` calls `strncpy()`
without including `<string.h>`, and GCC 14+ makes that a hard error. Upstream fixed it by
guarding the call with `#if LINUX_VERSION_CODE < KERNEL_VERSION(4,2,0)`. The akmod in
`atomic-camera/` is that same tag rebuilt with that two-line fix. If you rebuild it yourself,
apply the same guard.

**Why the sleep hook.** `facetimehd` redoes a full hardware bring-up on every resume (PCIe link
init, PLL lock, DDR calibration, 1.4 MB firmware reload) and is the most fragile thing in the
resume path. The hook unloads it before suspend and reloads it **detached**
(`systemd-run --no-block`), so a slow reload costs you the webcam, not the session.

**Verify:**

```sh
modinfo facetimehd | grep -E 'filename|firmware'
ls -l /dev/video0
journalctl -k -b | grep -i facetimehd | tail
```

A healthy bring-up logs `Found FaceTime HD camera with device id: 1570`, `S2 PCIe link init
succeeded`, `PLL reset finished`, `Full memory verification succeeded`, `Loaded firmware`, and
`ISP woke up`. The line `Direct firmware load for facetimehd/1871_01XX.dat failed with error -2`
is **expected** — the driver probes for a sensor set this machine does not have.

**Test it:** open any camera app, or `mpv av://v4l2:/dev/video0`.

**Undo:** see §12.

## 5. Keyboard backlight — optional

**Hardware:** the backlight is exposed by `applesmc` as the LED `smc::kbd_backlight`. The
kernel side already works.

**Why the keys do nothing by default.** On the MacBook the F5/F6 keys emit
`XF86KbdBrightnessDown`/`XF86KbdBrightnessUp`, but Fedora's Sway config only binds the *display*
brightness keys. So the keys are simply unbound.

**How `keyboard-backlight.sh` does it.** It writes
`~/.config/sway/config.d/80-keyboard-backlight.conf`, binding those keysyms to:

```sh
brightnessctl --class=leds --device=smc::kbd_backlight set 5%-
brightnessctl --class=leds --device=smc::kbd_backlight set +5%
```

`brightnessctl` writes the LED **as your user** (through logind), so no sudo is needed, and the
bindings use `--locked` so they work on the lock screen too.

**Verify:** press F5/F6; you should see the LED change and a notification. `status` mode prints
the current level.

**Undo:** `./keyboard-backlight.sh off` (or delete the drop-in and reload Sway).

## 6. Trackpad — optional

**Hardware:** `bcm5974`.

**The default** on Fedora's Sway is tap-to-click **off**, tap-and-drag **on**, and
`click_method=clickfinger` (a two-finger *press* is a right click).

**How `trackpad.sh` does it.** It writes `~/.config/sway/config.d/70-touchpad.conf`:

```
input "type:touchpad" {
    tap enabled
    tap_button_map lrm
    drag disabled
    click_method button_areas
}
```

which gives: one-finger tap = left click, two-finger tap = right click, tap-and-drag off, and a
hard press in the bottom-right corner = right click (regardless of finger count).

**The trade-off to know:** libinput can do **either** `clickfinger` **or** `button_areas`, never
both. `button_areas` (used here) makes the click depend on *where* you press, so a two-finger
*press* is no longer a right click — a two-finger *tap* still is. If you prefer two-finger press,
change `click_method` to `clickfinger` and reload.

**Undo:** `./trackpad.sh off`.

## 7. Fn/Ctrl swap — optional

**Hardware:** the kernel's `hid_apple` driver has a `swap_fn_leftctrl` parameter that swaps the
Fn key and left Control. It is evaluated on every key event, so it can be applied live through
sysfs.

**Why a systemd service and not `modprobe.d`.** On Atomic, `hid_apple` is loaded from the
**initramfs** (it registers the keyboard ~2.6 s in, before switch-root), so a `modprobe.d`
option in the real `/etc` is never seen at boot. `swap-fn-ctrl.sh` therefore writes the sysfs
parameter for the current session *and* installs a tiny oneshot service that re-applies it on
every boot.

**Verify:** `./swap-fn-ctrl.sh status`, or run `wev` and press the leftmost key (expect
`Control_L`).

**Undo:** `sudo ./swap-fn-ctrl.sh off`.

## 8. Key remapping in general, and the Caps-tilde swap — optional

There are two ways to remap a key on Linux, and which one you use depends on whether a driver
happens to expose the swap:

1. **Driver/kernel level** — when the driver has an option for it. `hid_apple`'s
   `swap_fn_leftctrl` (§7) is the example. This is the cleanest: it works system-wide, including
   on the text consoles.
2. **udev hwdb scancode remap** — when no driver option exists. This rewrites the *scancode* to
   a different keycode at the evdev layer, below the compositor, so it also works everywhere
   (Sway, the lock screen, SDDM, TTYs).

**The Caps/`` ` `` swap** (`swap-caps-tilde.sh`) is the worked example of the second kind, and it
is a **personal preference** — the setup script asks and defaults to no.

How the hwdb remap works, in case you want to remap something else:

1. Find the device's modalias: `cat /sys/class/input/inputN/modalias` (for this keyboard,
   `input:b0003v05ACp0291e0110-…`).
2. Find the HID usage of each key. USB-HID scancodes are `(usage_page << 16) | usage`; keyboard
   usages are on page `0x07`, so Caps Lock is `0x70039` and grave/tilde is `0x70035`. (The HID
   report descriptor in `/sys/class/hidraw/hidrawN/device/report_descriptor` confirms the page.)
3. Write the rule to `/etc/udev/hwdb.d/`:

   ```
   evdev:input:b0003v05ACp0291*
    KEYBOARD_KEY_70039=grave
    KEYBOARD_KEY_70035=capslock
   ```

4. `sudo systemd-hwdb update` and re-trigger the device (`udevadm trigger /dev/input/eventN`).

Two gotchas worth remembering:

- **`off` needs care.** systemd's keyboard builtin only ever *applies* mappings and never resets
  them, so `swap-caps-tilde.sh off` first writes the *default* keycodes back, then removes the
  rule.
- **A `/etc/modprobe.d` blacklist cannot stop an initramfs module.** The original runbook
  blacklisted `applespi` (a no-op SPI-keyboard driver for 2016+ Macs). On Atomic `applespi.ko`
  is baked into the initramfs and loads at ~9 s, *before* switch-root, so the blacklist never
  runs. This repo simply leaves it loaded — it binds nothing and is harmless. To actually remove
  it you would need to rebuild the initramfs with a dracut `omit_drivers`.

**Undo:** `sudo ./swap-caps-tilde.sh off`.

## 9. Lock screen and PIN — optional

**How locking works under Sway.** `swayidle` runs `~/.local/bin/lock-screen`, a small wrapper
that (for the swaylock modes) screenshots the desktop, blurs it, and launches the locker.
`~/.config/sway/config.d/90-swayidle.conf` overrides Fedora's default to use that wrapper.

**`lock-screen-setup.sh`** picks the look:

| Mode | Result |
|---|---|
| `blur` | blurred, darkened screenshot behind swaylock's ring |
| `solid` | clean dark background, swaylock ring |
| `gtklock` | login-style screen — clock, a **password text box**, and an Unlock button — over the blurred screenshot |
| `stock` | Fedora's default wallpaper look |

`gtklock` needs its package layered (`rpm-ostree install gtklock`, one reboot). It looks like a
login screen, which is why it is the recommended mode.

**The numeric PIN** (`lock-pin.sh`) is implemented with `pam_exec`:

- A helper at `/usr/local/sbin/lock-pin-check` is inserted into `/etc/pam.d/swaylock` and/or
  `/etc/pam.d/gtklock`, *before* `auth include login`.
- Your PIN is stored as a SHA-512 crypt hash in `~/.config/lock-pin` (mode 0600). Your real
  account password still works as a fallback, so you cannot lock yourself out.
- It rate-limits to 5 wrong PINs per 5 minutes, and only digit-only input counts as a PIN
  attempt, so typing your password is never throttled.

One subtlety that matters if you ever debug it: **`pam_exec` runs the helper with the PAM
environment, not your session environment**, so `HOME` is not set. `lock-pin-check` therefore
derives your home directory from `PAM_USER`/your real UID rather than `$HOME`.

**Undo:** `./lock-screen-setup.sh stock` and `sudo ./lock-pin.sh clear`.

## 10. Kernel upgrades

`wl` and `facetimehd` are out-of-tree and must be rebuilt for every new kernel. `akmods` does
this automatically, but **a kernel that boots fine can still have no wifi or no camera**, so
verify rather than assume. `atomic-upgrade.sh` wraps the whole thing:

- runs `rpm-ostree upgrade`;
- finds the **staged** deployment (`staged: true` in `rpm-ostree status --json` — *not* merely
  "not booted", which also matches the rollback);
- checks that `wl.ko` and `facetimehd.ko` were built for its kernel;
- tells you to reboot once they are.

```sh
sudo ./atomic-upgrade.sh
```

After booting a new kernel:

```sh
modinfo wl facetimehd | grep filename
nmcli -t -f DEVICE,STATE device | grep wlp3s0
```

## 11. Health check and troubleshooting

The setup script prints this at the end; you can reproduce the pieces by hand:

```sh
modinfo wl facetimehd | grep filename
ls -l /dev/video0
nmcli -t -f DEVICE,STATE device | grep wlp3s0
lsmod | grep -E '^wl |^facetimehd '
```

Expected-but-alarming-looking messages, all normal on this machine:

- `wl: module license 'MIXED/Proprietary' taints kernel.`
- `You are using the Broadcom STA wireless driver, … Proceed at your own risk!`
- `Unpatched return thunk in use. This should not happen!`
- `Direct firmware load for facetimehd/1871_01XX.dat failed with error -2`

If wifi dies after resume, check the sleep hook ran: `journalctl -b | grep -i wl-reload`, and
that `/etc/systemd/system-sleep/wl-reload` is labelled `bin_t` (`ls -lZ`). If the camera is
missing, check `journalctl -k -b | grep -i facetimehd` and that the akmod was built
(`ls /usr/lib/modules/$(uname -r)/extra/facetimehd/`).

## 12. Undo everything

Each piece is independent; deleting its files undoes it.

```sh
# Optional preferences
./keyboard-backlight.sh off
./trackpad.sh off
sudo ./swap-fn-ctrl.sh off
sudo ./swap-caps-tilde.sh off
./lock-screen-setup.sh stock
sudo ./lock-pin.sh clear

# Camera (packages + hook)
sudo rpm-ostree uninstall akmod-facetimehd facetimehd facetimehd-firmware
sudo rm -f /etc/systemd/system-sleep/facetimehd-reload

# Wifi (only after a replacement adapter works -- you will otherwise have no network)
sudo rpm-ostree uninstall akmod-wl broadcom-wl
sudo rm -f /usr/local/sbin/wl-fix-wifi-profiles \
           /etc/systemd/system/wl-fix-wifi-profiles.path \
           /etc/systemd/system/wl-fix-wifi-profiles.service \
           /etc/NetworkManager/conf.d/91-wl-no-pmf.conf \
           /etc/systemd/system-sleep/wl-reload \
           /etc/modules-load.d/wl.conf
sudo systemctl daemon-reload
```

`rpm-ostree uninstall` stages the change; reboot to apply. Every `rpm-ostree` change also keeps
the previous deployment available in the boot menu as a rollback.
